# 分支管理规范

## 分支约定

- `main`：稳定主干，保存可发布的版本；
- `dev`：集成分支，汇集各功能分支的改动；
- `feature/<功能名>`：新功能分支，例如 `feature/add-week-view`；
- `fix/<问题名>`：缺陷修复分支，例如 `fix/notice-reminder`。

## 工作流程

1. 从 `dev` 拉出功能或修复分支：

   ```bash
   git checkout dev
   git pull
   git checkout -b feature/add-week-view
   ```

2. 在分支上完成开发并提交，提交信息清晰说明本次改动。
3. 发起 Pull Request 合并回 `dev`，通过评审后合并。
4. `dev` 稳定后再合并至 `main`，并打上版本标签。

## 冲突解决

当两个分支修改了同一文件的同一位置，合并时会出现冲突：

1. 打开冲突文件，查看 `<<<<<<<`、`=======`、`>>>>>>>` 标记；
2. 对比双方改动，保留需要的内容，删除冲突标记；
3. 重新提交后完成合并。
